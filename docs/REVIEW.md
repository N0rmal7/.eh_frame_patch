# eh_frame_patch 1.0.0 评测与 1.0.1 优化报告

## 结论

原版具备清晰的核心分层和可运行的汇编/ELF 示例，但补丁导出和洞区选择存在高影响缺陷，界面在本次真实 IDA 渲染中也有明显异常。我的工程评分为 **6/10**：可作功能原型，不建议原样用于比赛交付。

优化版评为 **8/10**：关键路径已有真实 IDA + WSL 证据，适合在理解洞区和指令副作用的前提下使用。该评分是基于本次代码审查和场景验证的主观工程评价，不是标准化性能分数。

## 原版问题与处理

| 优先级 | 发现 | 本次处理 |
|---|---|---|
| P1 | 把 .eh_frame 最后 64 字节称为 safe area，未解析记录；打开编辑器还会悄悄改变目标地址 | 仅推荐终止记录之后的零填充；不移动用户指定地址，未发现填充时明确拒绝自动推荐 |
| P1 | 导出只看本插件当前会话的 _written_ranges，遗漏 Keypatch 的入口跳转，重开 IDB 后漏补丁 | 枚举 IDA 显式补丁记录，包含其他工具和 IDB 保存的记录，避免用全库差异混入加载器修正 |
| P1 | 导出直接将 IDA EA 当作 ELF VA，重定位数据库会出错 | 经 loader 文件偏移转换为 ELF VA，逐字节验证文件映射和原始内容，并合并连续区间 |
| P1 | “绝不修改原文件”只有文案保证，选择原路径仍会覆盖 | 底层写入拒绝原路径、符号链接和硬链接别名；使用唯一临时文件原子替换并保留模式位 |
| P1 | apply_patch 本身不拒绝含错误的计划，失败后可能保留部分写入 | API 自身验证计划和预览原字节，写入后回读，失败尝试恢复并回读，恢复失败明确报告 |
| P1 | 原生 Form 实际布局异常，复选框值未可靠进入计划 | 改为 PyQt5 同窗编辑/预览，直接读取选项，Patch 前重新计算；真实按钮点击验证 |
| P2 | 跨段放行时没有检查中间未映射字节，读取失败仍可视为有效计划 | 检查完整读取和实际写入区间映射，允许跨段不意味着允许空洞 |
| P2 | ELF 范围检查只判断文件末尾，允许跨越 PT_LOAD 文件区写入 BSS/其他内容 | 按整个文件支持的加载范围校验，拒绝不支持的扩展编号和截断/过短头表 |
| P2 | Undo 先弹出记录，写入失败后无法重试，后续编辑可能被覆盖 | 回读成功后才弹出记录；冲突及 rebase 后拒绝撤销；数据库关闭清空会话状态 |
| P2 | del_items 可能删除补丁范围外的完整结构；只生成一条指令就声称转换完成 | 预查既有数据项和全部指令边界；只有全范围创建成功才报告代码转换完成 |
| P2 | 符号替换会匹配数值中的 x10，标签解析后未更新分支目标检查，tab 分隔的 db 无法正确规范化 | 分开处理数值/字符串 token，更新符号解析后目标，支持空白分隔指令 |
| P2 | Ctrl+Alt+P 与 IDA 原生 Patched bytes 冲突，主快捷键重复注册 | 移除额外冲突快捷键，保留 Ctrl+Alt+J 和 Ctrl+Alt+Shift+J |
| P2 | 原测试脚本比较源文件与其自身，AWDP 脚本依赖 /tmp 现成文件且不严格断言 | 改用哈希检查、临时目录、退出码和输出断言；修正“端到端”脚本实际绕过插件导出的情况 |

P1 表示可能导致错误补丁、遗漏修复或破坏原文件；P2 表示边界/交互/验证可靠性问题。

## 本次验证

- 原版基线：30 项，Windows 29 通过、1 项 ELF 运行测试跳过。
- 优化版 Windows：47 项，43 通过，4 项因平台条件跳过。
- 优化版 WSL：47 项全部通过，覆盖 ELF32/ELF64 的真实运行及 AWDP main 的正常/漏洞触发路径。
- 真实 IDA Pro 9.0：23/23 项 API 检查通过，检查见 `evidence/ida_review.json`；包括注入部分写入失败后的恢复、Undo 失败保留历史、外部显式补丁、数据库 +0x100000 重定位后的导出。
- 真实界面：`evidence/ida_form_review.json` 和 `evidence/form.png`；修改汇编、预算、NOP，点击实际 Patch，验证最终接收的源文本与选项。风险确认被测试脚本自动应答，不声称人工检查了所有对话框。
- 插件端到端：实际 apply_patch → export_executable_copy 导出 main.e2e，验证入口/洞区字节、GOT 不变、leave/ret 不变、PF_X 设置；该副本在 WSL 下 exit、add、delete、double-delete 四个场景均退出 0，double-delete 返回 Invalid Index。
- 原安装位置及用户压缩包未替换；优化工作全部在独立副本中进行。未向现有安装目录部署。

## 使用上的变化

编辑器采用左右输入与预览，输入变化合并 180 ms，确认时同步重算，避免写入旧计划。默认预算最多 32 字节；NOP 默认关闭，填满整个预算时有明确提示。地址用十六进制，预算用十进制。Return VA 明确为说明信息，不自动生成 jmp。

更新需要同时替换入口 .py 与 ehp/ 目录并重启 IDA。不依赖修改 Keypatch 源码；在真实 IDA 测试中 Keypatch 动作仍然存在。

## 剩余限制

1. 本插件不证明任意 .eh_frame 区域可安全复用。样例显式覆盖活跃展开数据，只验证普通执行与漏洞修复，不保证异常/取消/回溯兼容。
2. 不自动搬迁原指令或重写 RIP 相对操作数，也不分析全部寄存器、标志位、栈对齐和控制流。跳板正确性仍需要逆向分析。
3. 增加 PF_X 影响整个 PT_LOAD，可能引入 RWX 或扩大执行区域；不代表符合比赛补丁规则或系统安全策略。
4. Undo 恢复字节，不恢复完整 IDA 数据项/类型/注释元数据；遇到后续修改或 rebase 拒绝覆盖。建议保留原 IDB。
5. 未在所有 ELF 变体、其他 IDA 版本和真实比赛 checker 下验证；扩展 ELF 头编号明确拒绝。
6. 没有安装 Capstone 时预览中的源码布局并非独立反汇编校验；本次 IDA 字节校验和真实执行提供另外的行为证据。

## API 依据

导出使用官方的 [visit_patched_bytes](https://python.docs.hex-rays.com/namespaceida__bytes.html) 枚举显式补丁，通过 [get_fileregion_offset](https://python.docs.hex-rays.com/namespaceida__loader.html) 获取文件偏移。使用真实 IDA API 的验证与普通 CPython 单测分开记录。
