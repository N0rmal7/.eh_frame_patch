# 使用流程

1. 保存数据库副本，检查原函数中 free 后的执行路径、入口可覆盖指令边界以及其他分支的落点。
2. 明确洞区范围。不要假定 `.eh_frame` 尾部就是空闲区；自动推荐只使用终止记录之后的零填充，通常可能找不到。
3. 选中洞区范围，Ctrl+Alt+J，输入修复指令及跳回指令。预算为十进制字节数，地址为十六进制。
4. 预览实际机器码和反汇编，检查指针存储槽、操作数宽度、寄存器/标志位影响。PIE 下务必验证 RIP 相对编码，不能照抄原指令的 rip+disp。
5. Patch。代码转换只在原有数据项和新指令都不越过补丁区间时进行；未转换不代表字节未保存。
6. 在入口写入跳转，并正确重现被覆盖指令的行为。插件不自动搬迁指令，也不自动修正手写 RIP 位移。
7. 导出可执行 ELF 副本。该操作读取整个数据库的显式补丁记录，包含 Keypatch 的入口跳转；不会把单纯加载器修正当成用户补丁。
8. 检查新增 PF_X 的整个 PT_LOAD、原文件是否未变，并实际执行功能路径和漏洞触发路径。

## 编辑选项

- NOP-pad 会覆盖整个预算，默认关闭；超过 1 MiB 的填充拒绝执行。
- 允许跨段不能允许未映射地址或无法完整读取的区域。
- Return VA 是说明信息，不会插入 jmp，也不是返回路径分析结果。
- Patch 后出现“代码转换未完成”时，字节可能已经保存；查看成功信息和数据库字节，不要盲目重复写入。
- Undo 是会话内的字节恢复，遇到后续编辑冲突时拒绝执行；不是完整数据库撤销。

## 风险边界

修改 CIE/FDE 可能影响异常、线程取消、回溯及某些运行库。程序普通路径正常退出不足以证明展开信息有效。
清空必须落在实际保存悬空指针的槽位上；清寄存器、局部副本不能消除其他别名。
自动推荐仅检查记录边界及零填充，不证明洞区无其他引用或满足比赛 checker。
